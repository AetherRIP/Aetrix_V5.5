# Scheme criteria extraction — version 1

You are transcribing the **mark points** a printed mark scheme awards, so the
engine can award them. Return one JSON object only. Do not add prose, Markdown,
comments or a code fence.

You are given:

- the approved blueprint: every scoreable question id and the marks the paper
  carries for it;
- the pages of the mark scheme, as images.

Transcribe only what the scheme prints. Never invent a mark point, a tolerance,
an expected answer or a question that is not printed on the pages. If a cell is
illegible, omit that mark point and record a note instead of guessing: a missing
mark point is refused by the coverage check and fixed by a person, while a
guessed one would be marked with.

## Coverage rules

- One entry per **scoreable leaf** of the blueprint. A question with
  subquestions is marked through its subquestions, so emit `16b`, not `16`.
- The mark points of a question must add up to exactly the marks the blueprint
  gives that question. Do not round, pad or drop a mark to make the sum fit.
- `code` is the printed code: `B1`, `M1`, `A1`, `M1FT`, `B2`, and so on. Do not
  rename a printed code.
- `ordinal` is the position of the mark point inside its question, starting at
  0. Two mark points may share a code; their ordinal keeps them distinct.
- `dependencies` names a printed condition such as `dep (ft)`: the codes this
  mark point needs. Leave it empty when the scheme prints none.
- `alternatives` records a printed alternative route that replaces other mark
  points. `replaces` must name the codes the route stands in for, and must
  include the code of the mark point that carries the route. Leave the list
  empty when the scheme prints no alternative route. A prose alternative with
  no code adds no mark point: record it in `description` instead.
- `expected_answer` is the scheme's own printed answer, verbatim enough for a
  computer-algebra comparison. Leave it null when the scheme does not print one
  unambiguously.
- `award_conditions` and `withhold_conditions` carry printed conditions such as
  `cao`, `oe`, `isw`, `SC` or a printed exception.

## Shape

```json
{
  "questions": [
    {
      "question_id": "1d",
      "source_ref": {"item": "1. June 15/4H/Q7 d", "pdf_page": 3},
      "criteria": [
        {
          "code": "M1",
          "marks": 1,
          "ordinal": 0,
          "description": "3 of the 4 terms of (y + 10)(y - 2) correct, or all 4 ignoring signs",
          "expected_answer": "y^2 + 8y - 20",
          "required_evidence": null,
          "dependencies": [],
          "alternatives": [],
          "award_conditions": null,
          "withhold_conditions": null,
          "source_page": 3,
          "source_quote": "M1 for 3 correct terms out of 4 or ... + 8y + c"
        },
        {
          "code": "A1",
          "marks": 1,
          "ordinal": 1,
          "description": "cao",
          "expected_answer": "y^2 + 8y - 20",
          "required_evidence": null,
          "dependencies": [],
          "alternatives": [],
          "award_conditions": "cao",
          "withhold_conditions": null,
          "source_page": 3,
          "source_quote": "A1 cao"
        }
      ]
    }
  ],
  "total_marks": 91,
  "notes": []
}
```

`total_marks` is the sum of the scoreable leaves you were given, not the sum of
the printed scheme total when the paper excludes a question. `notes` records
anything a reviewer must know: an excluded question, an illegible cell, a
printed typo.
